## What to post, and when

Rules:
- No posts asking people to test or sign up.
- Every number must match `evidence/claims.json` (`npm run evidence:verify`).
- Tag **@Firebase** and use **#BuildHybridAI** on product posts.

**Before submission (build in public, 3–4 posts, one every day or two):**

1. *Intro.* "Teachers mark piles of exercise books by hand, often with no data. We're building InkTally: photograph a handwritten page, the phone's own AI (Gemini Nano) reads it, code marks it against the teacher's marking guide, and the cloud double-checks when there's signal. #BuildHybridAI @Firebase", plus a 10-second clip of a page being marked.
2. *A real exam format.* "We wrote a WAEC-standard physics paper (objectives, structured questions, method marks, theory points) and answer scripts. InkTally keeps the paper's own labels like 6(b)(ii) and marks every answer by code." Add the agreement number from the WAEC evidence file once it's recorded, and a photo of a marked page.
3. *The honest catch.* "The AI read 'v = f/λ' as 'v = fλ'. Code caught it anyway: 50 ÷ 0.4 = 125 is correct arithmetic on the wrong formula, so no method mark, and it's flagged for the teacher." Include a screenshot of the flag.
4. *Offline.* A clip with airplane mode on: the page is marked and labelled "On this phone", then turns "Verified" when the signal returns.

**Submission day:** the pinned thread in [`../x-post.txt`](../x-post.txt).

## My view

Worth doing, at small effort. The thread is part of the submission package anyway. A real account with a few honest build posts makes InkTally look like a product, and the Grand Prize includes a featured blog post and social promotion. Don't chase followers; judges score the criteria.
